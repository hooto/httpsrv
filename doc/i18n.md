# i18n

In v2, i18n is an **opt-in module, not loaded by default**. When you need it, attach it to the App with `WithI18n` and pass the template function `i.Funcs()` to the template engine. Locale matching is a frozen RFC 5646 subset implemented inside the framework (`internal/langtag`): no third-party dependency, no CLDR updates to track.

The message store is the simplest form `locale -> key -> text` (**no singular/plural**); this module does not do date/number/currency/timezone formatting.

## Overview

| Capability | Entry point |
|---|---|
| locale detection | `app.Use(AcceptLanguage("en", "zh", ...))` middleware |
| read locale in a Handler | `c.Locale()` |
| translate in a Handler | `c.Translate(locale, key, args...)` |
| message store | `I18n` (`NewI18n` / `Add` / `Set` / `LoadJSON`) |
| translate in a template | `T` (injected by `i.Funcs()`) |

## 1. Accept-Language middleware

```go
app := httpsrv.New()
app.Use(httpsrv.AcceptLanguage("en", "zh", "ja")) // first is the default/fallback
```

- Parses the `Accept-Language` header and matches a supported locale (e.g. `en-US` -> `en`, `zh-Hans` -> `zh`).
- ISO 639 codes are canonicalized at parse time (171 frozen mappings in total: 146 ISO 639 aliases + 25 grandfathered whole tags). The aliases are a curated subset of commonly used languages, not an exhaustive list; a missing code is treated as an unsupported language: withdrawn 639-1 codes (`iw` -> `he`, `tl` -> `fil`), 639-2/B bibliographic codes (`ger` -> `de`, `chi` -> `zh`), a subset of 639-2/T three-letter codes for commonly used languages (`jpn` -> `ja`, `por` -> `pt`), and grandfathered whole tags (`i-lux` -> `lb`, `zh-min-nan` -> `nan`, `no-bok` -> `nb`). Underscore separators read as dashes (`en_US` = `en-US`), and bare language names occasionally sent by misconfigured clients (e.g. `english`) canonicalize to their code too.
- Match order, exact to loose: full tag exact (case-insensitive) -> same primary language -> macrolanguage family (`nb` -> `no`, `yue` -> `zh`, `prs` -> `fa`); members of one family never match each other (`nn` does not match `nb`).
- Entries are tried by descending q value; the first entry that matches wins. Among supported locales sharing a language, the first registered wins. Note the consequence: with `AcceptLanguage("en", "zh-Hant", "zh-Hans")`, requests such as `zh-CN`, `zh-TW`, or `zh-Hant-TW` all select the first-registered `zh-Hant` (script does not take part in the choice). Register the primary variant first.
- No CLDR inference (e.g. `sr` does not auto-prefer `sr-Cyrl`); when nothing matches, falls back to the first argument (the default).
- Malformed entries are skipped (including `q=NaN`), `q=0` and `*` are dropped, at most the first 100 entries are parsed, and a single tag is bounded to 256 bytes.
- The result is stored in the request context; read it with `c.Locale()`.
- The middleware does not set `Vary` automatically. If the response body varies by locale and passes through a shared cache (CDN/proxy), set `c.SetHeader("Vary", "Accept-Language")` in the handler, so the cache does not serve one language's page to another language's user.

## 2. Message store I18n (flat key -> text)

```go
i := httpsrv.NewI18n("en") // default language

// batch
i.Add("zh", map[string]string{"welcome": "欢迎", "hi": "你好 %s"})
i.Add("en", map[string]string{"welcome": "Welcome", "hi": "Hi %s"})

// single
i.Set("en", "bye", "Bye")

// load from JSON (flat {"key": "text"})
i.LoadJSON("en", []byte(`{"welcome": "Welcome", "hi": "Hi %s"}`))
```

Translate:
```go
i.Translate("en", "welcome")      // "Welcome"
i.Translate("zh", "missing")      // fall back to default -> then the key: "missing"
i.Translate("zh", "hi", "Alice")  // "你好 Alice" (args via fmt.Sprintf)
```

- Lookup chain: requested locale -> default locale -> the key itself.
- Locales are case-insensitive.
- When texts are formatted via `fmt.Sprintf`, a literal `%` must be written as `%%` (e.g. `"Save 50%%!"`); the key returned by the missing-key fallback is formatted as well.

## 3. Attach to the App (use in a Handler)

```go
app := httpsrv.New(httpsrv.WithI18n(i))

app.Get("/", func(c httpsrv.Ctx) error {
    return c.SendString(c.Translate(c.Locale(), "welcome"))
})
```

- Without `WithI18n`: `c.Translate(...)` returns the key unchanged (i18n module not loaded).
- Without the `AcceptLanguage` middleware: `c.Locale()` falls back to the i18n default, then the empty string.

## 4. Use in a template (T)

Pass `i.Funcs()` as extra template functions to the template engine:

```go
r, _ := httpsrv.TemplatesFS(views, i.Funcs())
app := httpsrv.New(httpsrv.WithViews(r), httpsrv.WithI18n(i))
```

Template: `<h1>{{T .Lang "welcome"}}</h1>`

## Full example

```go
package main

import (
	"embed"
	"io/fs"

	"github.com/hooto/httpsrv/v2"
)

//go:embed views
var views embed.FS

func main() {
	i := httpsrv.NewI18n("en")
	i.Add("en", map[string]string{"welcome": "Welcome"})
	i.Add("zh", map[string]string{"welcome": "欢迎"})

	sub, _ := fs.Sub(views, "views")
	r, err := httpsrv.TemplatesFS(sub, i.Funcs())
	if err != nil {
		panic(err)
	}

	app := httpsrv.New(httpsrv.WithViews(r), httpsrv.WithI18n(i))
	app.Use(httpsrv.AcceptLanguage("en", "zh")) // detect locale

	app.Get("/", func(c httpsrv.Ctx) error {
		return c.Render("home.html", map[string]any{"Lang": c.Locale()})
	})

	_ = app.Run(":8080")
}
```

`home.html`: `<h1>{{T .Lang "welcome"}}</h1>`
